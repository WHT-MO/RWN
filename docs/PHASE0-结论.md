# Phase 0 预研结论

日期：2026-10-16 · 状态：预研完成，待拍板 fork/自研

## 一、许可证结论（重大）

**RWPP 采用 AGPL-3.0**——最强传染性开源许可证：
- Fork 或复制其代码 → 我们分发的修改版**必须同样以 AGPL-3.0 开源**
- 对免费社区工具：可接受，开源甚至是声誉加分
- 影响评估：反作弊是"自证模式"，其有效性不依赖代码保密（作弊者本来就不跑我们的客户端），因此开源**不削弱**反作弊效果

## 二、RWPP 代码评估（28,000 行 Kotlin）

**可复用的核心资产**（约 6,500 行，质量尚可）：
- core-api 注入框架：`@Inject/@InjectClass/@SetInterfaceOn/@RedirectTo` 注解 + javassist 字节码改写器（KSP 编译期生成注入信息）
- desktop 层 20 个 Inject Hook 类：菜单替换、IME 修复、攻击范围按钮的具体实现

**技术路线已被验证**：
- 注入方式：classpath 注入（RWPP 自身为主类，游戏 jar 作库），首次运行 javassist 改写游戏类 → generated_lib/ → 重启生效
- 菜单替换：自有 JFrame + ComposePanel 覆盖游戏 Canvas，Override showMainMenu/showBattleroom 切换面板（"遮挡+短路"，非渲染 hook）
- IME 修复：游戏原生聊天弹窗被 Compose TextField 替代，走系统 IME 通道

**fork 的负担**：
- 注入层满是混淆名（bZ/bX/bS）与魔法字段，无测试，死代码多
- 耦合需手术切除：RCN 服务器协议、rtsbox.cn API、isPremium 硬编码、Android 模块
- 整体绑定特定混淆版 game-lib.jar（任何注入方案都有此约束，非 fork 独有）

## 三、RW 反编译源码关键定位（全部可行性：高）

引擎纠正：RW 是 **Slick2D + LWJGL2 + libRocket**（非 libGDX）。Compose 无法嵌入游戏 GL 画布，只能同 JVM 独立窗口/无边框叠加——RWPP 的"遮挡"方案是唯一正确路线，已被验证。

| 功能 | 类/方法 | 结论 |
|---|---|---|
| 战争迷雾 | `PlayerData.N`（byte[][]，≥5 可见 / <5 不可见 / 127 已探索）；重置 `PlayerData.a()`；全图重算 `class_484.f(float)` | 巡逻+恢复可行，且可"重算"而非仅"恢复缓存" |
| 中文聊天 | 直接反射调 `GameNetEngine.m(String)` 发送 | 无需碰输入框即可发中文，极简 |
| IME 根因 | LWJGL2 键盘轮询绕过系统 IME（`librocket.class_790` 逐字符转换） | 确认，Compose 替换弹窗是正解 |
| 出兵队列 | 工厂基类 `class_91.z`（`class_320`），队列 `c`（ArrayList），条目 `class_73`，入队 `class_320.a(...)` | 数据结构清晰，可实现队列管理 UI |
| 攻击范围 | `OrderableUnit.attackRange()`；渲染 hook 点 `class_694.a(Unit,float)` | 可给任意/敌方单位叠加范围圈 |

注意：反编译源 58% 文件仍是 class_NNN 混淆名，但引擎骨架已反混淆；RWPP 的 Hook 类提供了现成的"混淆名 → 用途"对照。

## 四、认知修正（两点）

1. **RWPP 当前版本并没有"工厂出兵队列管理"功能**（只有禁用单位和单位分组 UI）。你说的"RWPP 那种工厂出兵逻辑"需要我们自己实现——好在队列数据结构已定位清楚，实现路径明确
2. 迷雾反作弊比原设想更强：不只是"恢复被改的值"，可以周期性重算全图视野（调用游戏自己的重算逻辑），任何 CE 篡改都会被下一次重算覆盖

## 五、Fork vs 自研 —— 我的建议

**建议：Fork RWPP，激进裁剪 + UI 换血，接受 AGPL 开源。**

理由：
- 注入框架 + 菜单替换 + IME 修复是 RWPP 踩过坑才跑通的部分，自己重写要重踩一遍；其 core-api 设计干净，可长期使用
- 裁剪清单明确：删 android 模块（gradle 一行）、删 RCN/rtsbox/premium 耦合（约几百行手术）、UI 全换月轨风（UI 层与游戏层经事件总线解耦，是它做得好的地方）
- 全新自研的唯一优势（license 自由）对免费社区工具价值有限；AGPL 开源反而符合社区软件惯例
- 混淆名对照表（RWPP Inject 类 ↔ 反编译源码）是 fork 独有的加速器

**代价（知情）**：我们的仓库需公开源码；需理解其注入层才能安全裁剪。

若你坚持闭源 → 唯一路线是自研（只看 RWPP 学思路、不抄代码），工期约 3-4 倍。
